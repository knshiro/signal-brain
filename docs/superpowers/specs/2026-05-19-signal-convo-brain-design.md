# Signal Conversation Brain — Design

**Date:** 2026-05-19
**Author:** the operator (with brainstorming partner)
**Status:** Spec — awaiting review before implementation plan
**Scope:** target conversation (`out/<source>/`); designed for multi-source operation

---

## 1. Goal

Turn a long Signal conversation between two parties (typically thousands of messages) into a structured artifact that future agents can use as **personal memory** — so when an agent acts on the operator's behalf, it knows their positions, the other party's positions, recurring debates, examples cited, who said what, with citations back to exact messages.

Multi-source operation is supported: each conversation gets its own `brain/<name>/` folder, and the system can handle any number of sources independently.

Adapts Karpathy's LLM Wiki model (gist `442a6bf555914893e9891c11519de94f`) with one new page type (Position) that the debate format needs.

## 2. Source data

- `out/<source>/data.json` — JSONL, one record per message.
- Per-record fields: `date` (ISO ms), `sender` (`"Me"` | `"<source>"`), `body`, `quote`, `sticker`, `reactions`, `attachments`.
- Generated by `pipx install signal-export && sigexport`.
- Re-export will be run periodically. Must be cheap to incrementally ingest.

## 3. Layered architecture

```
L0  Raw messages         data.json (sigexport output, untouched)
L1  Bursts               time-gap clustering (mechanical, free)
L2a Topic-tagged bursts  LLM tags per burst, open vocabulary
L2b Arcs                 runs of same-topic bursts, narrative scope
L3  Wiki pages           Karpathy-style synthesis: People, Concepts, Positions, Arcs, Cross
L4  Indexes              index.md, log.md, lint-report.md; brain/AGENTS.md written once at brain root
```

L0 is immutable. L1 is deterministic and regeneratable. L2/L3 are LLM-generated and cached by content hash. L4 is built from L3.

## 4. Storage layout

```
signal-convo/
  out/<source>/             # raw sigexport input (immutable)
  brain/                    # gitignored except two files at the root
    AGENTS.md               # canonical agent reader's guide (committed)
    CLAUDE.md               # mirror of AGENTS.md (committed)
    <source>/               # per-source artifact (gitignored, regenerated locally)
      index.md              # auto-regenerated catalog
      log.md                # append-only ingestion/maintenance log
      lint-report.md        # latest health check
      data/                 # machine layer (regeneratable)
        msg_index.jsonl, bursts.jsonl, chunks.jsonl, arcs.jsonl
        manifest.json, link_graph.jsonl
      people/ concepts/ positions/ arcs/ cross/  # wiki pages
  scripts/                  # Python code
  docs/superpowers/         # specs + plans
  config.toml               # tunable knobs
  README.md / AGENTS.md / CLAUDE.md / KNOWN_ISSUES.md
```

Two rules:
- `brain/<source>/` is the unified human/agent-readable + machine layer. Nothing under `brain/<source>/` is committed. The brain-root `brain/AGENTS.md` and `brain/CLAUDE.md` are committed once as the canonical reader's guide.
- `out/` is the immutable source input.

## 5. L1 — Bursts

**Rule.** Split messages into bursts whenever `gap_between_consecutive_messages > burst_threshold`. Default threshold: **60 minutes**.

**Schema** (`data/bursts.jsonl`):
```jsonl
{"id":"B0042","start":"2026-05-05T13:18:00","end":"2026-05-05T14:02:00",
 "msg_ids":["2026-05-05T13:18:00.000::Me", "..."],
 "senders":{"Me":18,"<source>":17},
 "char_count":4231,"has_media":false}
```

**Stable message ID.** `msg_id = "{ISO-timestamp-ms}::{sender}"`. Computed once, cached in `msg_index.jsonl`. The composite key handles the rare millisecond collision.

**Burst-threshold evaluator** (one-shot tuning agent, `scripts/evaluate_bursts.py`).
After L1 runs, an agent samples ~20 burst boundaries, reads the last N messages of burst K and first N of burst K+1, and reports per-boundary: `natural` / `should-merge` / `should-split-elsewhere`. Aggregate verdict recommends keeping the threshold or trying another. Human approves before re-running L1 with a new value.

## 6. L2 — Topics and arcs

### 6a. Topics (`data/chunks.jsonl`)

Each burst gets 1–3 topic tags. **Open vocabulary** — LLM proposes freely; lint clusters synonyms.

**Defaults:** No seed tags and a neutral system prompt. Users can prime per-conversation via `config.toml`:
- `[tagging] description = "..."` — optional one-sentence conversational context hint.
- `[tagging] seed_tags = ["topic-a", "topic-b"]` — optional priming vocabulary.

For example, one might prime with `topic-a`, `topic-c`, `topic-d`, and `banter` as seed tags. The LLM will also propose new tags when needed. Lint clusters synonyms periodically.

**Schema:**
```jsonl
{"burst_id":"B0042","topics":["<topic-a>","<topic-b>"],
 "primary":"<topic-a>",
 "summary":"<operator> argues X; the other party disagrees."}
```

### 6b. Arcs (`data/arcs.jsonl`)

Consecutive bursts sharing the same `primary` topic, with ≥ 20 substantive messages of back-and-forth, fuse into an arc.

**Schema:**
```jsonl
{"id":"A007","slug":"topic-a-debate","period":["2026-05-04","2026-05-19"],
 "primary":"topic-a","bursts":["B0038","...","B0061"],
 "status":"unresolved","msg_count":342}
```

Arcs later get a markdown page at `wiki/arcs/A007-topic-a-debate.md`.

## 7. L3 — Wiki page types

Five page types. Each has YAML frontmatter for machine readability + a body with prescribed sections.

### 7.1. People — `wiki/people/{slug}.md`
```yaml
---
type: person
slug: <slug>
name: <Full Name>
relation: Me
languages: [...]
drivers: [...]
conversational-tics: [...]
sources_count: <N>
last_touched: <date>
---
```
Sections: `## Background` · `## Style & drivers` · `## Key positions` (links) · `## Recurring moves` · `## Open tensions` · `## Related` (auto-maintained).

### 7.2. Concepts — `wiki/concepts/{slug}.md`
```yaml
---
type: concept
slug: <concept-slug>
aliases: [...]
related: [...]
contested: true
sources_count: <N>
last_touched: <date>
---
```
Sections: `## What's at stake` · `## Sub-questions` · `## Empirical anchors` (cited evidence) · `## Positions on this concept` (links) · `## Related`.

### 7.3. Positions — `wiki/positions/{person}--{concept}.md` *(new page type, not in Karpathy)*
```yaml
---
type: position
holder: <holder-slug>
concept: <concept-slug>
stance: "..."
confidence: high
first_seen: [B0014#m3]
last_seen: [B0186#m22]
evolution: stable
sources_count: <N>
---
```
Sections:
- `## Core claim` (one sentence)
- `## Reasoning chain` (each step cited)
- `## Examples / evidence cited`
- `## Concessions made`
- `## Tensions with own other positions` (lint candidate)
- `## Evolution timeline`
- `## Counter-arguments faced`
- `## Related` (auto-maintained)

These are the pages an agent loads first when asked "what do I think about X?".

### 7.4. Arcs — `wiki/arcs/A{nnn}-{slug}.md`
```yaml
---
type: arc
id: A007
slug: topic-a-debate
period: [2026-05-04, 2026-05-19]
bursts: [B0038, B0061]
primary_topic: topic-a
status: unresolved
turning_points: [B0044, B0051, B0058]
---
```
Sections: `## Question at stake` · `## Opening positions` · `## Key turns` (quoted+cited) · `## Concessions & ground gained` · `## Why unresolved` · `## Related`.

### 7.5. Cross — `wiki/cross/{slug}.md`
Patterns across the corpus, created when lint flags ≥ N occurrences:
- `cross/agreements.md` — convergence points.
- `cross/disagreements.md` — irreducible forks.
- `cross/rhetorical-patterns.md` — recurring moves.
- `cross/empirical-pool.md` — recurring evidence pool: concrete examples cited multiple times across pages (historical events, statistics, named studies, etc.).

## 8. Naming, citation, language

**Slugs.** Lowercase, hyphenated, no diacritics. Examples: `bjork` (not `björk`), `topic-a-policy`.

**Position slug.** `{person}--{concept}` (double hyphen separator).

**Arc slug.** `A{3-digit}-{kebab-title}`.

**Citation format.** Compact `[B0042#m17]` (burst 42, 17th message in that burst — i.e. `bursts["B0042"].msg_ids[16]`, zero-indexed). Resolved by `scripts/resolve.py` to human form `(2026-05-05 13:18, Me): "..."`. Every claim in a wiki page must cite at least one message. Citations to messages that don't exist are caught by lint.

**Language.** Wiki content is in **English**. Quoted source material is **preserved verbatim in French** inside citations.

## 9. Incremental ingest

Re-export must not reprocess unchanged data.

**Manifest** (`brain/<source>/data/manifest.json`):
```json
{
  "last_processed_msg_ts": "2026-05-19T14:02:01",
  "burst_count": 187,
  "burst_threshold_min": 60,
  "content_hashes": {
    "B0186": "sha1:abc...",
    "B0187": "sha1:def..."
  },
  "schema_version": 1
}
```

**Re-export flow:**

1. **Diff.** Walk new `data.json` against `msg_index.jsonl`. Unknown `msg_id` → new. Known `msg_id` with body/reactions/attachments hash diff → modified.
2. **Tail-only L1.** Re-burst only the last existing burst + all new messages. Bursts before the last boundary stay frozen.
3. **Dirty-burst detection.** A burst is dirty if (a) new, (b) any message inside was modified, or (c) it's the previous tail burst whose extent changed.
4. **L2 cache reuse.** Hash each burst's content; if hash matches `manifest.content_hashes`, reuse topic tags from `chunks.jsonl`. Only dirty bursts call the LLM.
5. **Arc update.** Arcs touching the tail get re-evaluated. Arcs entirely before the tail are frozen.
6. **L3 propagation.** Wiki pages whose tags overlap with dirty bursts' tags get a `needs-update` flag in `log.md`. An ingest agent updates flagged pages' content (sections, not `## Related`).
7. **Append `log.md`.** `## [DATE] ingest | +47 msgs, +3 bursts, 2 arcs touched, 8 pages flagged`.

**Edge cases handled:**
- Message edited months later → hash mismatch → burst dirty → tags re-evaluated → pages flagged.
- Reaction added later → treated as content change, same path.
- Message deleted server-side → `msg_id` disappears → burst dirty.

**Full rebuild.** `scripts/rebuild.py --force` drops `manifest.json` and reprocesses everything. Expensive, always works.

## 10. Linking pass

Runs **after** L3 content generation, never interleaved.

### Stage 1 — Deterministic (no LLM)

From frontmatter alone:
- Position page with `concept: X` → ensure `[[concepts/X]]` in body and `[[positions/{holder}--X]]` listed on the concept page.
- Position page with `holder: <holder-slug>` → ensure listed on `[[people/<holder-slug>]]`.
- Arc's `bursts` overlap with bursts cited in a position → arc ↔ position linked both ways.
- Arc's `primary_topic` → arc ↔ concept linked both ways.

### Stage 2 — Lateral (LLM, per page)

For each page, agent reads the page + `index.md` and proposes lateral edges:
- Position → Cross (this position is one of the forks listed in `cross/disagreements`).
- Position → Position (cited concessions, direct counter-arguments).
- Concept → Concept (related concepts).
- Arc → Cross (this arc instantiates a rhetorical pattern).

Each proposed link is written to a `## Related` section at the bottom of the page. The section is **auto-maintained** — never hand-edited.

**Idempotent.** Re-running on unchanged pages is a no-op. Touched pages get only their `## Related` updated.

**Output.** Same wiki + `data/link_graph.jsonl` snapshot for fast traversal by agents.

## 11. Lint pass

Periodic health check (Karpathy's idea, adapted):

| Check | What it does | Auto-fix? |
|---|---|---|
| Unresolved citations | Every `[B…#m…]` resolves to a real message | No |
| Orphan pages | Page has zero inbound links | No (proposes delete or link) |
| Stale claims | Page hasn't been touched in N ingestions but its topic has new bursts | No (flags for review) |
| Tag synonyms | Cluster near-duplicate tags, propose merges | No (you approve) |
| Contradictions | Same holder, related concepts, claims that look opposed | No (flags for human) |
| Missing pages | Concept appears in ≥ 5 bursts but no concept page | No (proposes creation) |

Output: `brain/<source>/lint-report.md` (overwritten each run). Nothing auto-fixed.

## 12. Workflow

```
ingest (re-export landed)
  └─ diff messages → dirty bursts
  └─ L1 burst recompute (tail only)
  └─ L2a LLM tag dirty bursts → chunks.jsonl
  └─ L2b arc re-evaluate near tail → arcs.jsonl
  └─ L3 flag affected pages
  └─ L3 agent updates flagged pages (content only, not `## Related`)
  └─ link-pass (Stage 1 deterministic, then Stage 2 LLM lateral)
  └─ build_index.py (regenerate index.md)
  └─ append log.md entry

(periodic) lint
  └─ run all checks → lint-report.md
  └─ human reviews, approves merges/deletes/creates

(one-shot, on demand) evaluate-bursts
  └─ sample ~20 boundaries → verdict + threshold recommendation
```

Each step is its own script under `scripts/`. Composed via a Makefile or a thin `signal-brain` CLI. Agents pick them up individually too.

## 13. Open knobs & defaults

| Knob | Default | Notes |
|---|---|---|
| Burst threshold | 60 min | Evaluator agent recommends tuning |
| Min burst-count for an arc | 2 bursts | Both this AND msg-count must hold to form an arc |
| Min msg-count for an arc | 20 messages | Filters out chit-chat |
| Min occurrences for a Cross page | 3 | Below this, a pattern stays as a note on existing pages |
| Stale-claim ingestion count | 5 | Pages untouched for 5 ingests on active topics get flagged |
| Position evolution threshold | 2 distinct stance shifts | Flags `evolution: stable` → `evolution: shifting` |
| `[tagging] description` | _(empty)_ | Optional one-sentence conversational context hint |
| `[tagging] seed_tags` | _(empty list)_ | Optional priming vocabulary; LLM may also propose new tags freely |
| `[me] sender_label` | `"Me"` | The sender label in `data.json` that identifies the configured operator |
| `[me] slug` | `"me"` | Generic slug for the operator's wiki pages |
| `[me] name` | `"Me"` | Display name for the operator in generated content |

All knobs live in `config.toml`. Lint reports when current data suggests a knob is mis-tuned.

## 14. Out of scope (this iteration)

- Non-Signal sources (the broader "AI brain" mentioned in chat).
- Real-time ingestion. Re-export is manual.
- Embedding-based search (qmd). Index.md + grep is enough at this scale; revisit if pages > 500.
- Web UI / Obsidian integration. Plain markdown only.
- Multi-language wiki output. English only; quotes verbatim.

## 15. Acceptance criteria

A successful first build:

1. `brain/<source>/data/bursts.jsonl`, `chunks.jsonl`, `arcs.jsonl`, `msg_index.jsonl`, `manifest.json` all exist and validate.
2. Burst evaluator agent reports ≥ 80% "natural" verdicts on its sample.
3. `brain/<source>/` contains: 2 people pages, ≥ 15 concept pages, ≥ 15 position pages, ≥ 5 arc pages, ≥ 3 cross pages, plus `index.md`, `log.md`. `brain/AGENTS.md` and `brain/CLAUDE.md` exist at the brain root.
4. `link_graph.jsonl` shows every page has ≥ 2 inbound and ≥ 2 outbound edges (no orphans).
5. Every citation in every wiki page resolves cleanly.
6. Lint pass runs and produces a report.
7. Running a synthetic re-export (touching only the last 5 messages) updates < 5% of data files and < 10% of wiki pages.
8. Default config (no `[tagging] description` or `seed_tags`) produces zero conversation-specific terms in any generated output.
